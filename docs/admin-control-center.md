# Административный центр управления (Admin Control Center)

## Обзор

Административный центр управления — единая точка входа для управления всеми аспектами трекера. Реализован на основе единого файла с маршрутизацией по вкладкам (tab-based routing).

---

## Архитектура

| Компонент | Путь | Назначение |
|---|---|---|
| Точка входа | `admin.php` | Роутинг по вкладкам, подключение модулей |
| Модули | `app/admin/modules/*.php` | 8 функциональных модулей |
| Вспомогательные функции | `system/functions/functions.admin.php` | Общие хелперы для всех модулей |

**Принцип работы:** `admin.php` определяет активную вкладку через параметр `?tab=...` и подключает соответствующий файл модуля из `app/admin/modules/`.

---

## Вкладки и модули

### 1. Аккаунты (`tab=users_manage`)
**Файл:** `app/admin/modules/users_manage.php`

Управление пользователями трекера.

**Возможности:**
- Поиск пользователей по ID, имени, email, IP-адресу
- Фильтрация по классу, статусу (забанен / активен)
- Просмотр профиля: загрузки, скачивания, рейтинг
- **Действия с пользователем:**
  - Изменение класса
  - Бан / разбан, временный бан
  - Сброс passkey
  - Изменение email (только суперадмин)
  - Сброс аватара
  - Добавление заметки

**Безопасность:** все действия через POST + CSRF, логируются в `admin_audit_log`.

---

### 2. Комментарии (`tab=comments`)
**Файл:** `app/admin/modules/comments.php`

Модерация комментариев по разделам.

**Вкладки внутри модуля:** Торренты | Новости | Профили

**Возможности:**
- Поиск по тексту, пользователю, `torrent_id`, `news_id`, датам
- Удаление отдельного комментария
- Массовое удаление (только суперадмин)

**Безопасность:** все действия через POST + CSRF, логируются в `admin_audit_log`.

---

### 3. Жалобы (`tab=reports`)
**Файл:** `app/admin/modules/reports.php`

Обработка жалоб пользователей из таблицы `reports`.

**Возможности:**
- Список жалоб с фильтрацией по статусу (`new` / `in_progress` / `resolved` / `rejected`) и типу цели (`target_type`)
- Обновление статуса жалобы
- Назначение ответственного модератора
- Добавление комментария модератора

**Безопасность:** все действия через POST + CSRF, логируются в `admin_audit_log`.

---

### 4. Реклама (`tab=ads`)
**Файл:** `app/admin/modules/ads.php`

Управление рекламными слотами и объявлениями.

**Возможности:**
- Управление слотами (`ad_slots`): код, название, активность
- Управление объявлениями (`ads`) в рамках слота:
  - Название, HTML-код, URL изображения, целевой URL
  - Диапазон дат показа
  - Флаги: показывать гостям / пользователям, на десктопе / мобильных
- Переключение активности, удаление
- **HTML-код объявления** — только для суперадмина

**Безопасность:** все действия через POST + CSRF, логируются в `admin_audit_log`.

---

### 5. База данных (`tab=database`)
**Файл:** `app/admin/modules/database.php`

Инструменты для работы с базой данных.

**Возможности:**
- Список таблиц: количество строк, размер, движок, кодировка (`SHOW TABLE STATUS`)
- Операции над таблицами: CHECK, ANALYZE, OPTIMIZE, REPAIR
- Просмотр структуры таблицы (`SHOW COLUMNS`)
- Просмотр первых 50 строк — только для разрешённых таблиц: `categories`, `news`, `faq`, `torrents`, `priv`
- **Маскировка чувствительных полей** (не-суперадмин): `password`, `passhash`, `secret`, `token`, `remember`, `auth`, `session`, `passkey`, `email`
- **SQL-консоль (только суперадмин):** только `SELECT`, автоматический `LIMIT 100`, блокировка DML/DDL

**Блокируемые SQL-операции:** `DROP`, `DELETE`, `UPDATE`, `INSERT`, `ALTER`, `TRUNCATE`, `CREATE`, `REPLACE`

**Безопасность:** все действия через POST + CSRF, логируются в `admin_audit_log`.

---

### 6. Обслуживание (`tab=maintenance`)
**Файл:** `app/admin/modules/maintenance.php`

Управление режимом технического обслуживания сайта.

**Возможности:**
- Включение / выключение режима обслуживания
- Установка текста сообщения для пользователей
- Разрешение доступа для администраторов во время обслуживания
- Установка даты начала и окончания (автоматическое отключение при истечении)

**Хранение настроек:** через `lt_setting()` / `lt_setting_set()` в таблице `site_settings`.

**Безопасность:** все действия через POST + CSRF, логируются в `admin_audit_log`.

---

### 7. Кэш (`tab=cache`)
**Файл:** `app/admin/modules/cache.php`

Управление кэшем приложения.

**Возможности:**
- Информация о драйвере кэша (Memcached или файловый кэш)
- Статистика Memcached (если доступен): hits/misses, items, память, uptime
- Полная очистка кэша
- Инвалидация отдельных пространств имён: `settings`, `categories`, `torrent`, `user`
- Удаление кэша по конкретному ключу
- Graceful fallback при недоступности Memcached

**Безопасность:** все действия через POST + CSRF, логируются в `admin_audit_log`.

---

### 8. Система (`tab=system`)
**Файл:** `app/admin/modules/system.php`

Информационная панель состояния системы. **Только для суперадмина. Режим «только чтение».**

**Отображает:**
- Версию PHP, ОС, список расширений
- Версию MySQL
- Статус кэша
- PHP ini: `memory_limit`, `upload_max_filesize`, `post_max_size`, `max_execution_time`, `timezone`
- Права на директории: `uploads/`, `cache/`, `logs/`
- Последние 20 записей журнала аудита (`admin_audit_log`)

---

### 9. VIP / Plus (`tab=vip_plus`)

> ⚠️ **Заглушка.** Модуль не реализован. Отображается сообщение: «будет реализовано позже». Таблицы и бизнес-логика отсутствуют.

## Вспомогательные функции (`system/functions/functions.admin.php`)

| Функция | Описание |
|---|---|
| `lt_setting($key, $default)` | Чтение настройки из `site_settings` (кэшируется) |
| `lt_setting_set($key, $value, $admin_id)` | Запись настройки в `site_settings` |
| `lt_setting_preload()` | Массовая загрузка всех настроек |
| `lt_admin_audit_log($action, $module, $target_type, $target_id, $old_value, $new_value)` | Запись в журнал аудита |
| `admin_can($action)` | Проверка прав на одно из 15 действий |
| `admin_require($action)` | Проверка прав с вызовом `err()` при отказе |
| `lt_admin_role_label($user, $priv)` | Человекочитаемое название роли |
| `lt_admin_format_target($type, $id)` | Форматирование цели для журнала аудита |
| `lt_maintenance_mode_active()` | Проверка активности режима обслуживания |

## Таблицы базы данных

Миграция: `database/migrations/admin_control_center.sql`

### `admin_audit_log`
Журнал всех административных действий.

| Поле | Описание |
|---|---|
| `id` | Первичный ключ |
| `admin_id` | ID администратора |
| `action` | Название действия |
| `module` | Модуль, из которого выполнено действие |
| `target_type` | Тип объекта (user, torrent, comment и т.д.) |
| `target_id` | ID объекта |
| `old_value` | Значение до изменения |
| `new_value` | Значение после изменения |
| `ip` | IP-адрес администратора |
| `user_agent` | User-Agent браузера |
| `created_at` | Дата и время записи |

### `site_settings`
Настройки сайта, хранимые в базе данных.

| Поле | Описание |
|---|---|
| `id` | Первичный ключ |
| `setting_key` | Ключ настройки |
| `setting_value` | Значение |
| `setting_type` | Тип (string, int, bool и т.д.) |
| `description` | Описание настройки |
| `is_public` | Доступна ли настройка публично |
| `updated_by` | ID администратора, изменившего настройку |
| `updated_at` | Дата последнего изменения |

### `ad_slots`
Определения рекламных слотов.

| Поле | Описание |
|---|---|
| `id` | Первичный ключ |
| `code` | Уникальный код слота |
| `title` | Название слота |
| `description` | Описание слота |
| `is_active` | Активность слота |
| `created_at` / `updated_at` | Даты создания и обновления |

### `ads`
Отдельные рекламные объявления.

| Поле | Описание |
|---|---|
| `id` | Первичный ключ |
| `slot_id` | Привязка к слоту (`ad_slots.id`) |
| `title` | Название объявления |
| `html_code` | HTML-код баннера |
| `image_url` | URL изображения |
| `target_url` | Целевой URL |
| `is_active` | Активность |
| `show_to_guests` / `show_to_users` | Аудитория |
| `show_on_desktop` / `show_on_mobile` | Устройства |
| `starts_at` / `ends_at` | Период показа |
| `created_by` | ID создателя |
| `created_at` / `updated_at` | Даты создания и обновления |

### `reports`
Жалобы пользователей.

| Поле | Описание |
|---|---|
| `id` | Первичный ключ |
| `reporter_id` | ID пользователя, подавшего жалобу |
| `target_type` | Тип объекта жалобы |
| `target_id` | ID объекта жалобы |

| `status` | Статус: `new`, `in_progress`, `resolved`, `rejected` |
| `assigned_to` | ID назначенного модератора |
| `moderator_comment` | Комментарий модератора |
| `created_at` / `updated_at` / `resolved_at` | Временные метки |

## Роли и права доступа

Права проверяются через функцию `admin_can($action)` на основе флагов PRIV пользователя.

| Концепция роли | Ключ `admin_can()` | Требуемые флаги PRIV |
|---|---|---|
| Владелец / Суперадмин | `superadmin` | `EDIT_PRIV` |
| Менеджер пользователей | `users` | `EDIT_PRIV` или `user_add`, `setting_user`, `users_view` |
| Контент-менеджер | `categories`, `news`, `faq` | `EDIT_PRIV` или `cats`, `news_add`, `edit_news`, `faq_moderate` |
| Модератор торрентов | `torrents`, `reports` | `EDIT_PRIV` или `edit_release` |
| Модератор комментариев | `comments` | `EDIT_PRIV` или `comments_edit`, `comments_delete` |
| Системный администратор | `cache`, `database`, `maintenance`, `system`, `settings`, `ads` | только `EDIT_PRIV` |
| Администратор сессий | `sessions` | `EDIT_PRIV` или `sessions_view` |

## Защита и безопасность

| Механизм | Описание |
|---|---|
| CSRF-токен | Все POST-запросы валидируются через `lt_csrf_validate('admin_dashboard')` |
| Диалог подтверждения | Все деструктивные действия требуют подтверждения (`data-admin-confirm`) |
| Маскировка полей | Чувствительные поля (passkey, email) скрыты для не-суперадмина |
| Блокировка SQL DML/DDL | Модуль «База данных» блокирует: `DROP`, `DELETE`, `UPDATE`, `INSERT`, `ALTER`, `TRUNCATE`, `CREATE`, `REPLACE` |
| HTML в рекламе | Ввод HTML-кода объявлений — только для суперадмина |
| Аудит | Все изменения состояния записываются в `admin_audit_log` |
