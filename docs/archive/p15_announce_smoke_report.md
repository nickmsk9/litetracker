# P15 Announce Behavior Smoke Harness

Mode: smoke tooling only. No announce production behavior, accounting logic, protocol response logic, or schema changes were made.

## Created

- `tests/announce/announce_smoke.php`
- `docs/p15_announce_smoke_report.md`

## How to Run

From the local Docker PHP container:

```bash
docker compose exec php php -l tests/announce/announce_smoke.php
docker compose exec php php tests/announce/announce_smoke.php
```

If the host machine has PHP and can resolve the configured MySQL host, the same commands can be run without `docker compose exec php`.

## Covered Scenarios

| scenario | coverage |
| --- | --- |
| invalid passkey | Sends a 32-character unknown passkey, expects bencoded `failure reason`, and checks the token is not echoed back. |
| invalid info_hash | Sends a 20-byte zero hash, expects bencoded `failure reason`. |
| normal announce request shape | Sends a valid local torrent announce and checks for bencoded `interval` and `peers`. |
| compact=1 | Checks compact `peers` is a binary string with length divisible by 6. |
| event=started | Checks the announce path accepts the request without a failure reason. |
| event=stopped | Checks the stopped path returns a valid announce response without a failure reason. |
| left=0 seeder | Checks seeder classification does not crash or return a failure reason. |
| scrape.php basic | Checks scrape returns a bencoded dictionary with `files`. |

## Current Local Result

Latest local Docker run:

```text
PASS invalid passkey returns safe failure
PASS invalid info_hash returns failure
PASS normal announce shape returns interval and peers
FAIL compact=1 response shape
SKIP event=started does not crash
PASS event=stopped does not crash
SKIP left=0 seeder logic does not crash
PASS scrape.php basic response
```

The compact scenario currently fails because the response decodes as a valid
dictionary followed by trailing bytes (`0:ee` for empty compact peers). That is
a protocol correctness finding, not a harness crash.

`event=started` and `left=0 seeder` are skipped locally because `peers.prev_action`
is `NOT NULL` with no default, while the current announce insert does not write
that column. Under MySQL strict mode the insert fails before those scenarios can
be smoked safely.

## Data Requirements

The runner needs:

- At least one `torrents` row with a non-empty `infohash`.
- A matching local `trackers` row with `tracker='localhost'` for full announce success.
- A reachable local Docker database using the project config.
- PHP CLI with `mysqli`.

The invalid-passkey scenario can run without a valid user. Authenticated success cases are intentionally not required yet because P14 found local schema drift around `users.slots`.

## Safety Notes

- The runner uses unique `peer_id` values prefixed with `-P15SMK-`.
- Cleanup deletes only rows whose `peer_id` was generated by the runner.
- The runner snapshots and restores the selected local `trackers` counter row and selected torrent `completed`/`last_action`, because the production announce path can update them during valid smoke requests.
- It does not delete or rewrite unrelated peers.
- It does not modify `users`, `snatched`, or schema directly.
- If setup data is missing, the runner fails at setup instead of inventing fixtures.

## Skipped / Not Guaranteed

- It does not prove ratio accounting correctness.
- It does not prove completion is counted exactly once under concurrency.
- It does not test real torrent clients.
- It does not test IPv6 because the current announce path is IPv4-only.
- It does not test authenticated successful announce while the local `users.slots` drift remains unresolved.
- It does not guarantee production index performance; P14 report-only SQL remains the source for EXPLAIN checks.

## Risks Found While Building

- Immediate stopped cleanup cannot be trusted for a just-created peer because the current announce wait check can reject fast repeated announces. The runner therefore performs narrow direct cleanup of its own peer IDs.
- Valid guest announces can update local tracker counters and seeder `torrents.last_action`; the runner restores the local baseline after execution.
- Compact announce currently emits trailing bencode bytes for non-BitComet peers.
- Started/seeder insert paths are blocked locally by `peers.prev_action` strict-mode behavior.
